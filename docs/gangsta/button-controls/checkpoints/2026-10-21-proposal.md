# Proposer Proposal — button-controls

## Proposed Solution

### Architecture Overview

Three pure headers carry every decision the buttons make; the sketch keeps only pin reads, `millis()`, NeoPixel output and the EEPROM byte plumbing.

```
ButtonInput.h       raw sample -> debounced gesture     (Press | Hold | None)
RobotState.h        Machine{state, resume} + nextState()  <-- the only state assignment
PauseResume.h       which clocks/maneuvers a resume must reset
SmartTurn.h  (+)    planTurnResume(): the remainder of a timed pivot
CalibrationStore.h  Calibration struct, slot encode/decode, magic/version/seq/CRC
```

The state machine becomes a **`Machine` value** (`state` + `ResumeTarget`) rather than a bare enum, because "resume returns to the exact prior state" is *memory*, and memory in a pure transition function must live in the transition's own value. `postEvent()` becomes:

```cpp
q42::Machine g_machine = q42::machineInit();

void postEvent(q42::Event event) {
  g_machine = q42::nextState(g_machine, event);   // the ONE assignment
}
```

`nextState(const Machine&, Event)` replaces `nextState(RobotState, Event)` outright — the old signature is deleted, not kept as a wrapper, so every stale call site is a compile error rather than a silent behaviour change. All reads become `g_machine.state` (15 sites today).

State/gesture flow per loop pass (~200 Hz):

```
handleSerialCommands()
bench modes (g/j)  -> reset gestures, return
pollButtons()          two buttonTick() calls -> at most two postEvent()s
  onStateChanged(from,to) edge hooks: brake on Paused, reseed clocks on resume,
                                       run the sweep on Calibrate
switch (g_machine.state) { LineFollow / MarkerSettle / MarkerArmed / MarkerTurn /
                           Idle / Paused / AwaitingCalibration / Calibrate / Startup }
```

`Calibrate` is an **action state**: entering it runs the bounded sweep to completion and posts its own outcome. It has no per-tick behaviour and no exit except that event. That makes "you cannot be in Calibrate without having swept" structural.

### Key Technical Decisions

**1. Nine states, and `AwaitingCalibration` is a first-class refusal state.**

```cpp
enum class RobotState : uint8_t {
  Startup,
  AwaitingCalibration,  // no usable blob: motors braked, D41 refused, diagnostic repeats
  Idle,                 // calibrated, waiting for D41
  Calibrate,            // the bounded sweep is running
  LineFollow, MarkerSettle, MarkerArmed, MarkerTurn,
  Paused,               // motors braked; the maneuver to redo is held in `resume`
};
```

**2. `ResumeTarget` is its own enum, not a second `RobotState`.**

```cpp
enum class ResumeTarget : uint8_t { None, LineFollow, MarkerSettle, MarkerArmed, MarkerTurn };
inline RobotState resumeState(ResumeTarget t);   // None -> Idle (safe, non-driving)
```

**3. Twelve events; the *state* owns the meaning of a gesture.**

```cpp
enum class Event : uint8_t {
  None,
  BootCalibrated,      // setup(): a valid blob was loaded
  BootUncalibrated,    // setup(): no usable blob
  StartPause,          // D41 debounced press edge
  CalibrationHeld,     // D43 long hold reached 3 s
  CalibrationUsable,   // the sweep left a usable calibration (new or preserved)
  CalibrationUnusable, // the sweep left none
  MarkerSeen, MarkerSettled, MarkerAbandoned, JunctionReached, MarkerExpired, TurnComplete,
};
```

**4. Every transition, exhaustively.**

| from | event | to | resume |
|---|---|---|---|
| Startup | BootCalibrated | Idle | – |
| Startup | BootUncalibrated | AwaitingCalibration | – |
| AwaitingCalibration | CalibrationHeld | Calibrate | – |
| AwaitingCalibration | StartPause | **unchanged** (refused) | – |
| Idle | StartPause | LineFollow | – |
| Idle | CalibrationHeld | Calibrate | – |
| Calibrate | CalibrationUsable | Idle | – |
| Calibrate | CalibrationUnusable | AwaitingCalibration | – |
| Calibrate | StartPause, CalibrationHeld | **unchanged** (inert) | – |
| LineFollow | StartPause, CalibrationHeld | Paused | LineFollow |
| LineFollow | MarkerSeen | MarkerSettle | – |
| MarkerSettle | StartPause, CalibrationHeld | Paused | MarkerSettle |
| MarkerSettle | MarkerSettled | MarkerArmed | – |
| MarkerSettle | MarkerAbandoned | LineFollow | – |
| MarkerArmed | StartPause, CalibrationHeld | Paused | MarkerArmed |
| MarkerArmed | JunctionReached | MarkerTurn | – |
| MarkerArmed | MarkerExpired | LineFollow | – |
| MarkerTurn | StartPause, CalibrationHeld | Paused | MarkerTurn |
| MarkerTurn | TurnComplete | LineFollow | – |
| Paused | StartPause | `resumeState(resume)` | cleared to None |
| Paused | CalibrationHeld | Calibrate | cleared to None |
| Paused | any marker event | **unchanged** (slot preserved) | kept |

`nextState` has **no `default` branch** — a tenth state is a compile error. `Event::None` and any event a state does not own return `m` unchanged, resume slot included.

**5. `AwaitingCalibration` must accept D43, or a fresh board can never be calibrated.** Authority set is **Idle, AwaitingCalibration, Paused**:

```cpp
inline bool calibrateAuthority(RobotState s) {
  return s == RobotState::Idle || s == RobotState::AwaitingCalibration ||
         s == RobotState::Paused;
}
```

The predicate is used by `nextState` **and** by the serial `k` handler, so the two can never disagree.

**6. Gestures: `ButtonInput.h`, one tick per button per loop pass, no blocking.**

```cpp
constexpr uint16_t BUTTON_DEBOUNCE_MS  = 25;
constexpr uint32_t BUTTON_LONG_HOLD_MS = 3000;

enum class Gesture : uint8_t { None, Press, Hold };

struct ButtonState {
  bool     raw;
  bool     stable;
  uint32_t rawChangedAt;
  bool     pressedLatch;
  bool     holdFired;
  uint32_t pressedAt;
};

ButtonState buttonInit(bool rawPressed, uint32_t nowMs);
Gesture     buttonTick(ButtonState &b, bool rawPressed, uint32_t nowMs);
```

Semantics, each pinned by a test:
- `Press` fires once, on the debounced press edge (level read pressed continuously for `BUTTON_DEBOUNCE_MS`).
- `Hold` fires once, at `pressedAt + BUTTON_LONG_HOLD_MS`, only while still held.
- A press that reaches `Hold` never also emits `Press` on release; a release emits nothing.
- Re-arming requires a release: after a `Hold`, the next `Hold` needs a fresh press and another 3 s.
- A button already held at boot is seeded stable-pressed: no `Press`, but `Hold` 3 s later.
- All timing uses `uint32_t` subtraction, wrap-safe.

**7. Gesture → event mapping; short D43 and long D41 do nothing.**

| gesture | event | effect |
|---|---|---|
| D41 `Press` | `StartPause` | Idle→run, run→Paused, Paused→resume |
| D41 `Hold` | — | nothing extra |
| D43 `Press` | — | nothing |
| D43 `Hold` | `CalibrationHeld` | calibrate in Idle/Awaiting/Paused, else pause |

D41 acts on the press edge so pause is instant. D43 must not act on its press edge, or a mid-run 3 s hold would pause on press and calibrate at the 3 s mark.

**8. Gesture arbitration inside one tick: a stop outranks a start.** If D43 produced `Hold` this tick, the D41 `Press` is dropped (not deferred).

**9. Navigation gets explicit non-run cases and no `default`.** `decide()`'s `default:` is replaced by named cases for `Startup`, `AwaitingCalibration`, `Idle`, `Calibrate`, `Paused`, all returning `Event::None`, plus an exhaustive test per non-run state.

**10. `Paused` does no sensor reads, no PID, no marker polls**, brakes every pass, renders once on entry. `stopMotors()` is the L298N brake, not coast.

**11. Mid-marker pause, per maneuver (Don answer 2).**

| paused from | captured at pause | resume does |
|---|---|---|
| LineFollow | — | reseed PID clock, `previousError=0, integral=0`, `lastMarkerPollMs=now`, `markerArmedAtMs=now` |
| MarkerSettle | `settleCreepDone` | `markerSettle = markerSettleInit()`, `settleNextReadMs = now`, restore `settleCreepDone`; if the creep never ran, it runs now |
| MarkerArmed | — (context is globals) | `markerArmedSinceMs = now` (restart expiry), `lastMarkerPollMs = now`, reseed PID; `pendingAction` untouched |
| MarkerTurn | `pivotElapsedMs = now - turnPhaseStartMs` when `turnPhase == Coarse`, else 0 | re-plan the remainder (decision 12), never the duration |

The 50 ms creep is not re-driven when it already ran (re-driving backs the robot ~4 mm past the marks).

**12. The over-rotation hazard.** Two naive resume fixes are both wrong:
- leave `turnPhaseStartMs` alone → paused interval counts as pivot time → turn declared done with zero rotation;
- reset `turnPhaseStartMs = millis()` and keep Coarse → coarse phase runs the full 820 ms again → 60°+60° over-rotation.

Correct model: the rotation still owed is `fullTurnMs - pivotElapsedMs`.

```cpp
// SmartTurn.h
struct TurnResumePlan { bool complete; uint16_t remainingMs; };

inline TurnResumePlan planTurnResume(MarkerAction action, uint16_t fullTurnMs,
                                     uint32_t pivotElapsedMs) {
  TurnResumePlan p = {false, 0};
  if (action == MarkerAction::Straight || pivotElapsedMs >= fullTurnMs) {
    p.complete = true;
    return p;
  }
  p.remainingMs = (uint16_t)(fullTurnMs - pivotElapsedMs);
  return p;
}
```

Glue on resume into `MarkerTurn`:
- `complete` → `stopMotors(); markerArmedAtMs = millis() + MARKER_REARM_MS; postEvent(TurnComplete);` — zero extra rotation.
- otherwise → `turnFullMs = plan.remainingMs; turnPhase = TurnPhase::Coarse; turnPhaseStartMs = millis();`. With `TURN_COARSE_PERCENT = 100`, `coarseMsFor(remaining,100) == remaining`. The creep is skipped (already ran).

Re-planning into the closed-loop `Fine` hunt is rejected: the code records that the fine hunt was tried on the mat, never found the branch line, hunted to timeout and overshot.

**13. PID/marker clock reseeding on every resume.**

```cpp
struct ResumePlan {
  bool reseedPid;
  bool restartArmedExpiry;
  bool restartSettle;
  bool replanTurn;
};
inline ResumePlan planResume(ResumeTarget t);
```

`reseedPid` true for all four targets. `restartArmedExpiry` matters because `MARKER_EXPIRY_MS` is 1500 ms.

**14. The blocking sweep: keep it, but poll and consume.** `calibrateSensors()` renamed `runCalibrationSweep()`, keeps the bounded 10 s loop, gains `pollButtons()` each pass. Because `Calibrate` owns none of the button events, gestures raised during the sweep are consumed and dropped by `nextState` at the instant they happen. Gesture latches plus release-to-rearm mean a button still held when the sweep finishes produces nothing. Serial is not polled inside the sweep; `drainSerial()` before the sweep discards stale keystrokes.

**15. Serial `k` obeys the same authority rule.** Refused in driving states; in Idle/Awaiting/Paused it runs the same `runCalibrationSweep()` path (one code path), including the EEPROM write, landing in Idle on success. `s` still brakes unconditionally.

**16. EEPROM: two 64-byte slots at 0 and 64, double-buffered, magic written last.**

```cpp
constexpr uint32_t CAL_MAGIC   = 0x43323451u;  // 'Q''4''2''C'
constexpr uint8_t  CAL_VERSION = 1;
constexpr uint16_t CAL_SLOT_BYTES  = 64;
constexpr uint16_t CAL_SLOT_A_ADDR = 0;
constexpr uint16_t CAL_SLOT_B_ADDR = 64;
constexpr uint16_t CAL_REGION_BYTES = 128;
constexpr uint16_t CAL_PAYLOAD_BYTES = 44;
constexpr uint16_t CAL_MIN_SENSOR_SPAN = 50;
constexpr uint8_t  CAL_FLAG_LEFT_VALID  = 0x01;
constexpr uint8_t  CAL_FLAG_RIGHT_VALID = 0x02;
```

Slot layout (little-endian, packed by hand):

| offset | size | field |
|---|---|---|
| 0 | 4 | `magic` |
| 4 | 1 | `version` |
| 5 | 1 | `flags` (bit0 left colour valid, bit1 right) |
| 6 | 2 | `sequence` |
| 8 | 2 | `payloadBytes` (= 44) |
| 10 | 2 | reserved |
| 12 | 16 | `sensorMin[8]` uint16 |
| 28 | 16 | `sensorMax[8]` uint16 |
| 44 | 6 | left green thresholds |
| 50 | 6 | right green thresholds |
| 56 | 6 | reserved |
| 62 | 2 | CRC-16/CCITT-FALSE over bytes 0–61 |

The `valid` bool inside `GreenThresholds` is not stored; it lives in `flags`.

Write policy:
- Only from `Calibrate`, motors braked, sweep accumulates into a local `q42::Calibration`.
- Target slot = the one that is not the currently-valid newest (A if neither valid). `sequence = newestSeq + 1`.
- Byte order: payload 12–61, header 4–11, magic 0–3 last. Other slot never touched.
- `eeprom_update_byte` (skip matching bytes); worst case 64 × 3.3 ms ≈ 211 ms.
- **Verified by reading all 64 bytes back.** RAM committed only after read-back matches.
- A rejected sweep writes nothing and leaves live RAM untouched; `calibrationEncodeSlot()` returns false rather than emitting a degenerate blob.

**17. Boot sequence with the journal disabled.**

```
Serial.begin(115200)
pinMode(START_BUTTON_PIN/CAL_BUTTON_PIN, INPUT_PULLUP) + seed gesture machines from live pins
strip.begin/clear/show; motor pins + setMotor(0); colourSensorsBegin()
Calibration cal; CalLoadResult r = q42::calibrationLoad(slotA, slotB)   // 128 eeprom_read_byte
  Valid -> copy into sensorMin/sensorMax/g_leftThresh/g_rightThresh,
           g_colourCalFailed = !(left.valid && right.valid)
postEvent(Valid ? BootCalibrated : BootUncalibrated)
  Valid   -> Idle               : ready cue (3 green full-display flashes, 120 ms on/off)
  Missing -> AwaitingCalibration: amber, 300 on / 300 off, forever
  Corrupt -> AwaitingCalibration: amber, 120 on / 130 off, forever
previousTime = micros(); previousError = 0; integral = 0;
serial summary: source slot, sequence, per-sensor span, colour validity
```

`setup()` never enters `LineFollow`, never sweeps, never touches EEPROM, never waits for a serial key. `logHold`, the journal dump and `delay(1000)` are gone.

**18. Diagnostics: added to `LedDisplay.h`, illuminators always lit.**

```cpp
enum class LedColor : uint8_t { Off, White, Green, Red, Amber, Illum };

ledIdleFrame()                              // display OFF, illuminators ON
ledPausedFrame()                            // pixels 3 and 4 WHITE
ledAwaitingCalibrationFrame(t, corrupt)     // whole display AMBER, blinking forever
ledReadyFrame(on)                           // all 8 display pixels GREEN
```

Idle/Paused render once on entry; Awaiting renders only on blink edge change, keeping `strip.show()` off the 200 Hz path.

**19. Journal disable: call sites deleted, code kept.** Delete `journalPump()`, every `journalOffer(rec)`, the `setup()` journal dump, `logHold`, `journalBegin/NextGen/Flush` calls. Keep `Journal.h`, `LogBuffer.h`, `g_log`, the ring and its `x`/`z` commands. `e`/`q` print `JOURNAL DISABLED -- see the re-enable note in Journal.h`; `z` clears only the RAM ring. `Journal.h` gets a comment-only note: calibration region owns 0–127; before re-enabling, move the blob to 3966 and set `JOURNAL_SLOTS = 220`.

**20. Physical constants.** `START_BUTTON_PIN = 41`, `CAL_BUTTON_PIN = 43` as `const int`; `BUTTON_PRESSED_LEVEL = LOW`.

### Inverse Reasoning: Potential Harms

1. Accidental brush of D41 starts the robot. L: Medium / I: High. Mitigation: 25 ms debounce, hardware RC note, serial panic stop.
2. A resumed pivot lands on the wrong heading (battery sag, brake quantisation). L: Medium / I: Medium. Remainder never exceeds the original plan.
3. A new state slips into `decide()`'s old `default:`. L: Low / I: High. `default:` deleted + exhaustive signal matrix test.
4. A `Paused` machine resumes into the wrong maneuver. L: Low / I: High. Distinct `ResumeTarget` enum, slot preserved by every non-`StartPause` event, `resumeState(None) = Idle`.
5. Power loss during the 211 ms write. L: Low / I: Low–Medium. Two slots; previous blob intact.
6. Calibration region collides with a future journal re-enable. L: Low now / High later / I: Medium. Migration numbers written down; half-done re-enable lands in `Corrupt` → refuses to run.
7. A failed sweep looks like a successful one. L: Medium / I: Medium. Red failure cue, serial line naming the failing sensor/flank, return to `Idle`.
8. The 10 s sweep is uninterruptible. L: High (noticed) / I: Low. Bounded, named, motors braked, operator holding the robot.
9. Button leads pick up motor EMI. L: Medium / I: High. RC recommendation, debounce, checklist item; needs bench evidence.
10. The 3 s D43 pause latency. L: Certain / I: Medium. D41 is the instant pause; documented.
11. Losing the journal's post-mortem. L: Certain / I: Medium. Accepted cost.
12. `AwaitingCalibration` is a hard stop on the field. L: Low / I: High. Two slots; recovery is a button, not a laptop or power cycle.

### Constitution Compliance

| Rule | How it is met |
|---|---|
| Pure logic in host-testable headers | Four pure headers + `SmartTurn`; only pins/millis/EEPROM bytes/NeoPixel in the sketch; no Arduino stubs. |
| `nextState()` is the only state assignment | `g_machine = q42::nextState(g_machine, event)`; the bare `robotState` variable is deleted. |
| TDD: failing test first | Each header lands with its test red first. |
| NEVER require a laptop/serial key/input for a run | All controls are buttons; boot never blocks on Serial. |
| NEVER sweep with motors live | `runCalibrationSweep()` brakes first; only enterable from Idle/Awaiting/Paused. |
| NEVER require a power cycle | Rejected sweep, corrupt blob, failed write all recover via a D43 hold. |
| NEVER ship a magic number | All timings/offsets/flags named. |
| NEVER `delay()` block in a mission FSM state | Resume/Idle/Paused/Awaiting contain no delay; `Calibrate` is the documented bounded exception. |
| Green = direction, junction = when | Untouched. |
| No spec identifiers in source/tests/docs | Prose and constant names only. |

### Questions for the Don

1. May D43 calibrate from `AwaitingCalibration`? Read literally, "Idle or Paused only" would make a fresh board uncalibratable. Included in the authority set — confirm.
2. D41 acts on the press edge, not release/hold. Accidental brush starts the run; long hold does nothing extra. Alternative: start needs a 500 ms hold, pause instant. Which?
3. Marker settle replay: five fresh readings, but do not re-drive the 50 ms creep if it already ran. Confirm, or replay the creep too.
4. Turn resume: a new plan for the remainder (`fullTurnMs − pivotElapsedMs`), never the full duration, never the closed-loop fine hunt. Confirm.
5. A D43 hold mid-run pauses only after the full 3 s (pausing on press edge would also calibrate on the same hold). Accept the 3 s of travel, with D41 as instant stop?
6. A rejected sweep with a good previous blob keeps the old blob and returns to `Idle`. Alternative: any failed calibration clears the blob.
7. Blob validity does not require colour success; only blank/corrupt/degenerate line data refuses the start. Confirm.
8. `Idle` is a quiet display (display pixels off, illuminators on) after a three-flash ready cue. Prefer a steady "ready" pattern instead?
9. The 10 s sweep stays blocking but polls its buttons. Confirm the bounded deviation from "never `delay()` in an FSM state".
