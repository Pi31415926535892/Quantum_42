# Devils-Advocate Attack

## Open Idea Concerns

- The phrase "resumes from where it left off" overpromises. With the Don's rulings, resume is "resumes the run; any special maneuver restarts from its trigger", not "continues the interrupted maneuver".
- D41 press-edge start is a hair-trigger at `baseSpeed = 200` (`Robocup.ino.ino:213`). The Don has since chosen hold-to-start, which answers this.
- A 3 s hold is a long time to keep a moving robot's button down; the only instant stop was D41, and `s` is not a stop.
- `Calibrate` is a blocking action disguised as a state: unobservable, un-abortable, re-entrant (the sweep posts its own outcome from inside the edge hook). No re-entrancy guard specified.
- `AwaitingCalibration` is an addition beyond "Idle or Paused only"; necessary, but must be stated in the contract rather than buried in the authority predicate.

## Architectural Flaws

1. **Turn-resume capture is phase-blind and reproduces over-rotation.** `TURN_90_MS = 820` (`:659`), `TURN_COARSE_PERCENT = 100` and `TURN_FINE_MAX_MS = 0` (`:679-681`), `coarseMsFor(fullTurnMs,100) == fullTurnMs` (`SmartTurn.h:114-118`), and `turnPhaseStartMs` resets on every phase change (`:1192-1195`). A pause in the one-tick `Fine` phase captures `pivotElapsedMs = 0` → plans a full 820 ms remainder → ~120° for a 60° turn.
2. **A pause during `Creep` drops the un-run creep.** Creep is 30 ms at duty 150 (`:677-678`), skipped only for a U-turn (`SmartTurn.h:109-113`). Capture is 0 before Coarse, and the resume path jumps to Coarse, so the pivot happens off the junction's leading edge (~4 cm short).
3. **"No `default` ⇒ compile error" is false.** `g++ ... -Wall -Wextra -Wpedantic` with no `-Werror` (`test/run_tests.sh:23`); missing enum arms are `-Wswitch` warnings. `renderFrame` enumerates Green/Red/White/Illum/Off with no default (`:121-142`). Adding `LedColor::Amber` without teaching the renderer compiles and renders **black** after `strip.clear()`, so the awaiting diagnostic is invisible.
4. **Removing `logHold` without re-basing `logInit` writes out of bounds.** `g_log` is `.noinit` (`:715`) and `logInit` is called only in the cold-boot `else` (`:1695-1697`). `logPush` indexes `ring.rec[ring.head]` with no bound check (`LogBuffer.h:82-86`). Keep the ring, delete the probe, and the first run after cold boot writes through garbage `head`/`count`.
5. **Resume sub-state lives in untested sketch globals**, contradicting the "memory belongs in the transition value" rationale: `settleCreepDone`, `pivotElapsedMs` new globals, and `turnPhase`, `turnPhaseStartMs`, `turnFullMs`, `markerArmedSinceMs`, `settleNextReadMs`, `markerSettle` remain globals (`:720-736`). The bug in flaw 1 is in the untestable part.
6. **"Turn complete" posts `TurnComplete` from a state where the table says it is inert.** Ordering of `applyResume` vs. the state assignment is unspecified; if the hook runs before the assignment the event is dropped and the machine strands in `Paused`.
7. **`Idle → LineFollow` does not reseed the PID clock.** Only resume does. `setup()` seeds once (`:1748`); `dt` comes from `micros() - previousTime` (`:428-435`). Dormant while `Ki = Kd = 0` (`:194-196`) but a windup spike the moment they are enabled.
8. **The "10 s sweep" is ~13.6 s.** 10,000 ms loop (`:327`) + `calibrationComplete()` 500 ms (`:95-105`) + `colourFailureCue()` up to 2,850 ms (`:291-301`) + ~211 ms EEPROM write = ~13.6 s, during which `StartPause` is inert.
9. **`TURN_COARSE_PERCENT == 100` is an unstated precondition of the resume arithmetic.** `turnStep` reads live `cfg.coarsePercent` (`SmartTurn.h:114-118`); the sketch invites lowering it (`:674-676`). `planTurnResume` does not take the config.
10. **Validation is span-only.** `blackness()` returns 0 when `max <= min` (`Junction.h:41-47`), `rowPosition` returns CENTER when all sensors are zero (`:402-404`), so a stored inversion drives straight. `GreenThresholds::valid` (`ColourCalibration.h:179-186`) is never consulted by `looksGreenCalibrated` (`:245-257`), so `flags`/`g_colourCalFailed` alone do not force the default thresholds.
11. **Slot arithmetic contradicts itself.** `payloadBytes = 44` at offset 8 vs. "payload 12–61" (50 bytes); reserved bytes 10–11 and 56–61 unspecified, making CRC and read-back non-deterministic. Literal offsets are magic numbers.
12. **`Paused` does read sensors**: `sensorTelemetryTick()` (`:1816`) precedes the state switch, doing eight `analogRead`s (`:1608-1611`) and I²C.
13. **The proposed `check-hardware.py` checks cannot pass alongside boot seeding.** `constant()` matches `const int NAME = <digits>;` (`:49-51`); "only two digital reads" fails with four textual call sites; "journal never written" must target `journalOffer(`/`journalPump(`/`journalFlush(`, not `eePush(`; active-LOW cannot be verified by grep and must be tagged **UNVERIFIED** per `HARDWARE.md:19-20`.

## Security Concerns

1. **No working remote stop.** **CRITICAL.** `s` brakes and returns (`:1403-1407`); the loop re-drives in `lineFollowTick` (`:1788-1789`). Any serial byte also clears `logHold` (`:1359`).
2. **25 ms brush starts the robot at full base speed.** **HIGH.** (Answered: hold-to-start.)
3. **Button electrical convention unverified and undiagnosed.** **HIGH.** If wired to +5 V, pins read HIGH forever: no start, no calibration, and no button-state readout anywhere.
4. **A failed EEPROM write discards a good RAM calibration.** **MEDIUM.** Read-back-gated commit with no "run on this session's measurement" mode makes a marginal EEPROM brick the robot. (Answered: run on RAM, warn.)
5. **`Calibrate` has no abort and no watchdog.** **MEDIUM.** A hung `Wire.requestFrom`/`SoftWire` means the only calibration path hangs; recovery is a power cycle, which the constitution forbids.
6. **The amber frame must not repaint pixels 8–11.** **MEDIUM.** Illuminators are part of the optical path (`LedDisplay.h:8-15`, `:104-109`). "Whole display AMBER" would light the next sweep amber and bias colour thresholds. No test asserts `pixels[8..11] == Illum` for the new frames.
7. **`AwaitingCalibration` ignores D41 with no feedback.** **LOW.** Indistinguishable from a broken button; a short red flash on the refused press would fix it.

## Constitution Violations

- **`delay()` in mission FSM states:** `markerSettleTick` 50 ms (`:1117`), `lineFollowTick` 5 ms (`:1803`), `calibrationComplete()` 500 ms (`:95-105`), `colourFailureCue()` up to 2.85 s (`:291-301`). The compliance table claims only `Calibrate` is an exception — false.
- **`nextState()` is the only state assignment — and the only home for resume memory.** Resume sub-state lives in globals.
- **Pure logic in host-testable headers.** Capture arithmetic, creep/fine choice, gesture arbitration (decision 8), and `applyResume` reseeds are all in the sketch; they are decisions, not I/O.
- **NEVER ship a magic number.** Literal slot offsets; unevidenced `CAL_MIN_SENSOR_SPAN = 50`; hidden `TURN_COARSE_PERCENT == 100` precondition; CRC polynomial/init/refin/refout named only as "CCITT-FALSE".
- **HARDWARE.md must agree with the firmware.** Proposed check set is self-contradictory and tags an unverified electrical decision as **CODE**.
- **NEVER require a laptop for a run.** Recovery from a dead button or dead EEPROM cell is `k` over serial.
- **NEVER let a failure require a power cycle.** A hung sweep has no abort.

## Regression Risks

- **The enum reorder renumbers every `LogRecord.state`** (raw `uint8_t`, `LogBuffer.h:42`) against the stale legend at `:1435`; `.noinit` records also survive a re-flash.
- **First boot after flashing goes to `AwaitingCalibration`, not a run** — journal magic `0x4A324C51` (`Journal.h:48`) ≠ `CAL_MAGIC`; intended, but operator habit and `HARDWARE.md:164` are now wrong.
- **`k` mid-run refusal changes the bench workflow** (superseded: the Don has ruled serial behaviour unchanged).
- **The boot colour-failure cue is dropped** (`:1744`); a colour-invalid but line-valid blob runs silently.
- **`Idle` is visually dark** after the ready cue.
- **`g`/`j` bypass the FSM** (`:1818-1826`); toggling off resumes a `LineFollow` robot with a stale PID clock. Buttons are not polled in those modes.
- **`Paused → Calibrate → Idle` abandons the run.**
- **`journalOffer` is dead code that references the deleted `robotState`** (`:919-933`, especially `:925`) — compile error if only the variable is deleted.
- **Every `k` now writes EEPROM**, unlike today's RAM-only behaviour.

## Scalability Issues

- Fixed v1 44-byte payload; v2 needs a migration and unknown versions land in `Awaiting`.
- The journal re-enable is a comment, not a checked invariant; needs a `static_assert` or a script rule.
- `ResumeTarget` does not model sub-state; another phased maneuver repeats flaw 1.
- The action-in-an-edge-hook pattern nests transitions; a `stepAction()` called from the state switch would not.

## Verdict

**REJECT.** Three defects are fatal to the field story — phase-blind turn capture (1–2), out-of-bounds ring write after removing `logHold` (4), and the false "no default ⇒ compile error" guarantee that lets the amber diagnostic render black (3) — plus the advertised panic stop not being a stop (Security 1).

## Questions for the Don (all since answered)

1. Turn resume model → **drop the turn entirely; resume to LineFollow.**
2. `s` as a real stop → **serial behaviour unchanged; D41 is the field stop.**
3. Calibration from Paused abandons the run → **accepted (calibration returns to Idle).**
4. EEPROM write failure → **run on RAM, warn, recalibrate next boot.**
5. MarkerSettle creep replay → **any special process is fully dropped and restarted if paused.**
6. Colour-invalid blob cue → unanswered; apply the existing fallback + red cue.
7. Sensor span floor → unanswered; keep named, tag UNVERIFIED, measure on the bench.
8. Wiring evidence tag → unanswered; tag **UNVERIFIED** in HARDWARE.md with a bench checklist item.
